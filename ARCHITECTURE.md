# Architecture

Suniko Home is a single-page Tizen web app: one `index.html`, a set of ES5 scripts loaded in order, no framework and no build step. The same files run on the TV and in a desktop browser (`dev-server.py`). This document explains how the pieces fit, and the rules that keep the app smooth on TV hardware.

## Principles

- **Outside on the sky, inside on glass.** Clock, date and weather are written directly on the background; everything about the home sits on liquid-glass panels.
- **Readable from the couch.** Nothing smaller than 22 px; no all-caps labels; high contrast is protected by capping the sky's brightness.
- **Remote first.** Every action is reachable with arrows, OK and Back; the mouse support in the preview is a convenience.
- **Never blank.** Every data source is cached in `localStorage`; on start the last data is shown at once and refreshed in the background.
- **The TV GPU is the budget.** See [Performance rules](#performance-rules).

## Script order and modules

`index.html` loads, in this order:

| Script | Global | Responsibility |
|---|---|---|
| `config.example.js`, `config.js` | `CONFIG` | Defaults, then the user's overrides (`config.js` is optional and ignored by git) |
| `secrets.js` | `SECRETS` | Generated by `gen-secrets.sh` at build time (OAuth client and tokens) |
| `i18n.js`, `i18n/tr.js`, `i18n/en.js` | `I18N` | `t(key, params)`, language/locale resolution, number/hour formats |
| `weather.js` | `TVWeather` | Location (`CONFIG.location` → IP → SmartThings home → `CONFIG.fallbackLocation`, else an error state) and the Open-Meteo forecast |
| `smartthings.js` | `STHome` | Device polling, normalization, commands, scenes, OAuth renewal |
| `themes.js`, `scene.js` | `TVThemes`, `TVScene` | Photo theme catalog; the illustrated weather scene |
| `prayer.js` | `TVPrayer` | Diyanet / Aladhan times, location matching, calendar cache |
| `vendor/qrcode.js` | `qrcode` | QR generation for the developer hub (MIT; license in `vendor/qrcode.LICENSE.txt`) |
| `hn.js`, `github.js`, `status.js` | `TVHN`, `TVGitHub`, `TVStatus` | Developer hub data |
| `screens.js` | `TVScreens` | Top menu, screen registry and switching |
| `devhub.js` | `TVHub` | Developer hub rendering, focus, details panel |
| `demo.js` | `TVDemo` | Replaces `STHome` and `TVWeather` with fakes when `?demo` or `CONFIG.demo` |
| `app.js` | `TVDebug` | Wires everything: rendering, panels, settings, notifications, key handling |

Data modules never touch the DOM and never make a request while loading; they start when `app.js` (or a screen) calls `start()`. This is what lets `tools/test-hub.js` load them in Node.

## Screens and panels

- **Screens** are full-size layers. The home screen is always at the bottom; the developer hub (`#dev`) is an opaque layer that fades in above it (opacity only, 250 ms). When the fade ends, the home layers get `visibility: hidden` (`.home-off`) and the weather scene pauses, so the TV does not draw what nobody can see. `TVScreens.register(id, { show, hide, onKey, enabled })` adds a screen; the menu icon is `.mi[data-screen=id]` in `index.html`.
- **Panels** slide over the current screen: home controls (`#sheet`), settings (`#prefs`), and the theme and prayer-location pickers. Only one is open at a time (`panel` in `app.js`).
- **Notifications** stack at the top right, newest first, at most three, on every screen.

### Key routing

`app.js` has one `keydown` handler, evaluated in this order:

1. An open panel handles the key (settings rows, pickers, home controls; Back closes).
2. If the top menu is active, `TVScreens.menuKey` handles it.
3. If the current screen is not home, its `onKey` gets the key; if it returns `false`, **▲** opens the menu and **Back** returns home.
4. On the home screen: **▲** menu, **◀** settings, **OK/▼/▶** home controls.

Focus inside panels uses real DOM focus and the `[data-nav]` attribute (`move()` picks the nearest element in the arrow's direction). The menu and the developer hub use a `.focus` class instead, which keeps their styling independent of the panel focus ring.

A safety rule from a real incident: anything that closes by itself on a timer (panels after 30 s, the menu after 8 s) closes **without choosing anything**, so a stray key press afterwards cannot trigger a scene.

## Data flow and caching

| Source | Refresh | Cache key | Notes |
|---|---|---|---|
| Open-Meteo | 15 min | `tvwx_v1`, location `tvloc_v1` | One request for current, hourly and 7-day data |
| SmartThings | 20 s idle, 12 s with controls open | `tvcache_st` | One request (`/devices?includeStatus=true&includeHealth=true`); the API allows 10 per minute |
| Prayer times | about a month per fetch | `tvprayer_v1`, `tvprayer_place_v1`, `tvprayer_lists_v1_*` | Diyanet by district in Turkey, Aladhan elsewhere |
| Hacker News | 5 min, only while the hub is open | `tvdev_hn_v1` | Order from Firebase `topstories`, data from Algolia `front_page`; missing items from Firebase |
| GitHub | 1 h, only while the hub is open | `tvdev_gh_v1` | Unauthenticated search (10/min); on 403/429 waits for `X-RateLimit-Reset` |
| Service status | 2 min, always (for notifications) | `tvdev_status_v1` | Atlassian Statuspage `summary.json`; stops when the hub is hidden in settings |
| Settings | on change | `tv_prefs_v1` | Initial values from `CONFIG.display` |

**Notifications are differences**, never states: the app compares the previous and the new snapshot (doors, leaks, presence, batteries; pinned service components). The first live result after start is a baseline, and cached data never produces a notification.

**External text** (story titles, comments, repository descriptions, incident names, device names) is never translated and is always written with `textContent` or escaped HTML. Hacker News comment HTML is reduced to plain text by a pure function (`TVHN.text`).

## Internationalization

- Every visible string goes through `t('key')`; the key exists in **both** `app/i18n/en.js` and `app/i18n/tr.js`. Static HTML uses `data-i18n` and `data-i18n-aria`.
- Dictionary values can be functions for grammar (Turkish suffixes, English plurals).
- Formats follow the locale: dates (`date.long`), 12/24-hour time, decimal separator, percentages, hour labels. Temperatures are Celsius internally and converted for display.
- Language "auto" follows the TV's menu language; unit "auto" uses Fahrenheit for US locales.
- `node tools/check-i18n.js` verifies that both dictionaries have the same keys and that every key used in code exists.

## SmartThings authorization

- OAuth 2 with an `API_ONLY` SmartThings app and the redirect `https://httpbin.org/get` (the user copies the code from there). `st_auth.py` prints the authorize address and exchanges the code.
- Access tokens last 24 hours; **refresh tokens rotate on every renewal** and last 30 days.
- The TV's token pair is bundled into the build and then renewed **on the TV**, stored in `localStorage` (`st_oauth_v1`); a rebuild never overwrites a newer pair (`issued_at` wins).
- **Pitfall:** a second authorization with the same OAuth app returns the *same* token pair, so two clients (TV and desktop preview) cannot have independent tokens from one app; whichever renews first logs the other out. The desktop preview therefore uses **its own OAuth app** (`secrets/st-app-dev-created.json`). `st_auth.py` refuses to save a pair identical to the other client's, and never renews a pair it shares with the TV.
- The desktop preview proxies `/st/*` to the SmartThings API (which sends no CORS headers) and **blocks device commands by default**; `ST_WRITE=1` allows them on purpose. On the TV, requests go directly to the hosts allowed by the `<access>` list in `config.xml`; a new data source must be added there, or the TV blocks it.

## Performance rules

These come from measurements on a 2024 Samsung TV; the desktop browser hides all of them.

1. **No `backdrop-filter` on anything that moves.** Panels slide with the blur off (`.glass.moving`, an opaque color computed from the sky) and get the blur back after `transitionend`. Focus scaling also waits until the slide ends.
2. **Watch the compositing budget.** Every composited layer is redrawn on every frame. With the settings drawer open, the weather theme went from 25 layers to 13 after:
   - drawing the clouds once into a half-resolution canvas per band instead of many CSS-blurred boxes,
   - drawing the stars once into an image instead of a live canvas,
   - limiting the hills to the bottom strip of the screen,
   - removing empty full-screen layers (rain, lightning, fog) from the tree when they are not needed.
3. **Pause what nobody watches.** The weather scene pauses while any panel is open and while another screen is shown (`TVScene.pause`).
4. **Animate only what the GPU animates cheaply.** In the settings drawer, focus changes animate only `transform`; the ring, shadow and background switch instantly, because an animated `box-shadow` forced a repaint of the row and of the blurred glass behind it on every frame. Follow this for new focusable lists (the home controls and pickers still use the older, fully animated transition).
5. **Lists in `overflow: hidden` boxes clip focus rings**: use `scroll-padding` and enough side padding for the focus scale.

Use Chrome DevTools' Layers panel (or `LayerTree` over the DevTools protocol) to check the layer count when you change the scene or a panel.

## Testing and debugging

- `npm test` runs all three checks below; CI (GitHub Actions) runs them on every push and pull request, together with Python and shell syntax checks and an XML check of `config.xml`.
- `node tools/test-hub.js`: unit tests for the pure functions of the developer hub (story merging, comment text, status components and transitions, GitHub query).
- `node tools/check-i18n.js`: dictionary parity and key usage.
- `node tools/lint.js`: the app code parses as ES5, and no JavaScript, CSS, HTML, XML, SVG, Python or shell file contains comments.
- `python3 dev-server.py` and `http://127.0.0.1:8770/?demo`: the full app with sample data.
- Console helpers (`TVDebug`): `notify`, `open('prefs' | 'sheet')`, `sky(hour)`, `scene(cond, hour)`, `daylight(hour)`, `prayer(h, m)`, `prayerNotify(h, m)`, `screen('dev')`, `status(name, state)`, `hubFail(bool)`.
- On the TV, remote debugging over `sdb` is not available on every model; verify visually and keep changes measurable in the browser first.
